# ADR-023: Account-Bound Prop-Firm Risk Mode

**Status:** Accepted for implementation  
**Date:** 2026-09-19  
**Owners:** ATLAX Engineering

## Decision

ATLAX exposes an administrator-only Telegram switch for the risk policy applied
to the currently connected MetaTrader 5 account:

- `NORMAL_ACCOUNT`
- `PROP_FIRM_SHADOW`
- `PROP_FIRM_ENFORCED`

The switch selects a risk policy. It does not change the MT5 login, broker
server, terminal, or account. Prop-Firm mode requires an explicit binding to
the connected MT5 login, server, currency, and optional terminal instance,
plus a typed, versioned, source-backed Prop-Firm rule profile.

The live Risk Engine receives a `PropFirmRiskContext` only after the binding,
profile, account snapshot, and configuration pass validation. Missing, stale,
or mismatched data blocks new entries. Existing protective trade management
remains subject to the approved Prop-Firm protection guard.

## Rationale

MT5 does not provide a universal, trustworthy flag that identifies an account
as a Prop-Firm account. ATLAX therefore uses an auditable operator binding
instead of guessing from broker labels or account names. The policy switch
must not create the illusion that it selected another account.

## Consequences

- Normal account behavior remains unchanged when `NORMAL_ACCOUNT` is active.
- Shadow mode produces evidence without changing live order decisions.
- Enforced mode applies the selected loss budget before lot sizing.
- A changed MT5 login or server automatically blocks new Prop-Firm entries.
- Multi-terminal account routing is outside this decision and requires a later
  architecture decision.
- Telegram and logs show the active mode, account identity, profile version,
  and verification status without exposing credentials.
