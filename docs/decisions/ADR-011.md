# ADR-011: Deterministic Key-Level Evaluator

Status: Accepted  
Date: 2026-08-14  
Decision owner: Project Lead

Approval: Explicit V1 approval recorded on 2026-08-14.

## Context

ATLAX already stores `parent_at_htf_zone` as CRT quality metadata and exposes a
subscriber `Key-Level Only` preference. The runtime did not yet compute that
metadata, so the preference correctly failed closed but could not admit an
alert.

## Decision

Build a separate deterministic Key-Level Evaluator. It evaluates closed parent
candles independently of CRT detection and passes only quality metadata to the
existing detector/strategy pipeline.

Version 1 uses Previous Day, Previous Week, and confirmed H4/D1 fractal swings.
It uses MT5 broker D1/W1 bars for period boundaries and a configurable
ATR/price tolerance. The evaluator returns actual matched prices and an
immutable configuration snapshot ID.

Multiple matches remain metadata-only in V1. The existing HTF-zone confidence
weight is applied once. Additional confluence scoring requires a new decision.

## Consequences

Positive:

- Key-Level Only becomes deterministic and auditable.
- No CRT detector or execution boundary is changed.
- Matched levels can be compared in Signal Passport analytics.
- Standard users can continue receiving both key-level and open-structure
  setups.

Costs and risks:

- MT5 must provide additional closed D1/W1/H4 history.
- `UNKNOWN` handling is required when history is incomplete.
- Turning the existing HTF-zone factor from UNKNOWN into true/false may change
  confidence scores, so operational confidence-impact monitoring remains
  required after rollout.
- The V1 level definitions and tolerance are approved by this decision.

## Rollback

Disable live metadata injection or the evaluator setting. Standard and Premium
ATR routing continue using the last approved behavior. Key-Level Only remains
fail-closed when the evaluator is disabled or unavailable.
