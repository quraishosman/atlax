# ADR-008: PostgreSQL as Shared Production Storage

Status: Accepted
Date: 2026-08-09

## Context

ATLAX currently stores analytics in SQLite and subscriber, payment, runtime,
and audit state in local files. The scanner, API, Telegram bot, and dashboard
must eventually share one durable source of truth.

## Decision

Use PostgreSQL as the canonical production storage engine. Google Cloud SQL
for PostgreSQL is the first managed deployment target. Keep local SQLite and
JSON storage as a development and rollback source until all repository
adapters have been migrated and verified.

The migration starts with a versioned schema and idempotent importer. A live
cutover is allowed only when the scanner, API, bot, and dashboard have all
switched together.

## Consequences

- Cross-process payment, subscriber, Signal Passport, and audit consistency
  becomes possible.
- Backups, restore testing, access control, and TLS become deployment
  responsibilities.
- PostgreSQL credentials must be supplied through secret-managed environment
  configuration.
- Cloud SQL cost and network availability become production dependencies.
- SQLite and JSON code must not be removed until migration rollback is proven.
