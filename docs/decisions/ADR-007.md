# ADR-007: Subscription Lifecycle Maintenance

Status: Accepted
Date: 2026-08-09

## Context

ATLAX uses a scanner process and small persistent JSON stores for Telegram
payments and subscriber access. Subscribers need expiry reminders, automatic
suspension, auditable payment transitions, and an admin revenue summary.

## Decision

Run a short, idempotent subscription lifecycle maintenance pass from the
existing scanner loop. Persist payment status history and reminder delivery
markers in the existing stores. Keep payment approval manual and expose
confirmed-only revenue aggregation to the admin Telegram console.

## Consequences

- There is no second worker with a competing source of truth.
- Restart recovery uses persisted timestamps and markers.
- Reminder timing is bounded by the configured scanner poll interval.
- A stopped scanner delays reminders and expiry processing until startup.
- External payment rails remain manual-review integrations; no provider
  credentials or automatic payment verification are introduced.
- Lifecycle failures are isolated and logged without stopping market scanning.
