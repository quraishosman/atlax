# ADR-016: Controlled Automatic MT5 Execution

Status: Accepted for controlled live execution  
Date: 2026-08-17  
Decision owner: Project lead

## Context

ATLAX was generating risk-approved execution requests, but the deployment was
configured with `approval.require_manual: true`. Requests stayed `PENDING`
until an administrator approved them and then expired after the configured
five-minute window. The project lead approved automatic MT5 execution for the
current deployment after confirming that the MT5 terminal Algo Trading switch
is enabled.

## Decision

Set `approval.require_manual: false` for the controlled live deployment.

Automatic execution is permitted only through the existing boundaries:

- the Strategy Engine creates the candidate;
- the Confidence Engine supplies the documented score;
- the Risk Engine must approve the request;
- the Approval Engine marks only risk-approved requests as approved;
- the Execution Engine performs MT5 `order_check` before `order_send`;
- the broker result, execution record, and reconciliation state are logged.

The system must fail closed on invalid requests, failed preflight checks,
unsupported symbols or filling modes, terminal trading restrictions, ambiguous
broker responses, or missing execution data.

## Consequences

Risk-approved candidates can place MT5 orders without a Telegram admin click.
The terminal and broker remain independent gates, so enabling this setting
does not guarantee that every candidate will fill. Existing expired `PENDING`
requests are not replayed; only new requests created after the scanner restart
can enter automatic execution.

The deployment must monitor `approved_request_execute`, `execution_start`,
`execution_preflight_rejected`, `execution_unhandled_error`,
`approved_request_execution_complete`, and MT5 position reconciliation events.
