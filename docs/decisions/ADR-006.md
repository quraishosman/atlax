# ADR-006: Signal Passport Uses The Existing Alert UUID And Journal

Status: Accepted  
Date: 2026-08-09

## Context

ATLAX already creates a UUID for each `AlertEvent`, stores signal metadata in
the SQLite journal, and tracks live outcomes in `SignalTracker`. Creating a
second identity system would make history and performance reports disagree.

## Decision

The existing `AlertEvent.alert_id` is the permanent Signal Passport ID. It is
stored as `journal_entries.record_id`, and the existing SQLite journal is the
authoritative Passport store.

Passport lifecycle fields and deterministic pair/style aggregates are added
around that store. The Signal Passport remains in the Analytics layer and is
read-only to Telegram subscribers.

## Consequences

- Existing signal IDs remain stable across restarts and delivery views.
- Historical records can be migrated without changing detector or strategy behavior.
- Outcome tracking and history use one source of truth.
- The existing tracker remains responsible for determining monitored outcomes; the Passport only records them.
- Subscriber reports exclude account and execution-side data.
