# ADR-017: Volume Profile Confluence — Phase 0 Governance Approval

Status: Accepted  
Date: 2026-08-17  
Decision owner: Project lead  
Authority: `docs/40_VOLUME_PROFILE_CONFLUENCE_PLAN.md`

## Context

`docs/40_VOLUME_PROFILE_CONFLUENCE_PLAN.md` defines a Volume Profile Confluence
feature that adds Previous Day and Previous Week POC, VAH, and VAL levels as an
independent, explainable confluence source for the Key-Level Evaluator. The plan
listed six open decisions that required project-lead approval before coding could
begin. The project lead has reviewed the plan and resolved all open decisions.

## Decision

Approve `docs/40_VOLUME_PROFILE_CONFLUENCE_PLAN.md` as the authoritative
specification for the Volume Profile Confluence feature. Implementation must follow
the phased rollout defined in §9 of that document.

### Resolved Open Decisions

| # | Decision | Approved value |
|---|---|---|
| 1 | Volume source for V1 | MT5 `tick_volume` as primary; `real_volume` when available from the terminal. Neither combined from multiple brokers nor claimed as consolidated global Forex volume. |
| 2 | Source timeframe — Forex non-JPY | M15 |
| 2 | Source timeframe — Forex JPY | M15 |
| 2 | Source timeframe — Gold/metals | M5 |
| 3 | Bin size — Forex non-JPY | 10 ticks |
| 3 | Bin size — Forex JPY | 10 ticks |
| 3 | Bin size — Gold | 20 ticks |
| 3 | Value-area percentage | 70 % (0.70) |
| 3 | Allocation method | `RANGE_UNIFORM` |
| 4 | V1 profile levels | POC, VAH, and VAL only. HVN / LVN deferred to a later proposal. |
| 5 | Minimum shadow cohort | 3–5 trading days with a meaningful resolved-signal sample before approving a confidence weight. |
| 6 | Premium Confluence satisfaction | Any one matched profile level (POC, VAH, or VAL from any approved profile period) satisfies the preference. |

### Phase Boundaries

The phased rollout from §9 is approved:

- **Phase 1** — Extend the MT5 candle model and feed to carry `tick_volume` and
  `real_volume`. Add `VolumeProfileConfig` to the Settings Engine.
- **Phase 2** — Implement a stateless Volume Profile calculator (POC / VAH / VAL,
  completed periods only, deterministic tie-breaking).
- **Phase 3** — Integrate Volume Profile as a named provider in the Key-Level
  Evaluator using the approved tolerance formula.
- **Phase 4** — Enable shadow mode (`shadow_mode: true`). Log counterfactual
  confidence results. Do not change delivery or execution.
- **Phase 5** — Store Volume Profile metadata in the Signal Passport and add
  approved Telegram alert context.
- **Phase 6** — After shadow review, approve a numeric confidence weight (requires
  separate project-lead decision and a rulebook or ADR update).
- **Phase 7** — After a separate approval, add the Premium Confluence preference
  (`require_volume_profile_confluence`).

## Constraints

The following constraints carry over unchanged from the plan:

- The CRT detector must not be modified. Volume Profile must not decide whether
  a CRT exists.
- An `UNKNOWN` Volume Profile result must not suppress a standard CRT alert.
- A confidence weight must not be applied until Phase 6 is explicitly approved.
- The Premium Confluence preference must not be enabled until Phase 7 is
  explicitly approved.
- Volume source limitations must be disclosed in admin and analytics views; broker
  tick volume must never be presented as consolidated global Forex volume.

## Consequences

- Volume Profile implementation may now begin at Phase 1.
- All implementation must comply with `docs/40_VOLUME_PROFILE_CONFLUENCE_PLAN.md`
  and the decisions recorded in this ADR.
- Subsequent phases that alter confidence scoring or Premium routing require a
  separate project-lead decision before promotion.
- The approved configuration schema from §8 of the plan is the required starting
  point for `VolumeProfileConfig`; deviations require a rulebook or ADR amendment.
