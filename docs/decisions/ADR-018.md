# ADR-018: Immediate Execution Is Independent of FVG Retests

Status: Accepted  
Date: 2026-09-19  
Decision owner: Project lead

## Context

ATLAX was treating a detected lower-timeframe Fair Value Gap as an execution
gate. Candidates were stored with `execution_ready=false` and could remain
unexecuted when price never revisited the FVG zone. This caused valid,
risk-approved CRT opportunities to be missed.

## Decision

Set `fvg.execution_gate_enabled: false` for the live deployment.

FVG detection remains available as confidence and confluence evidence. It does
not delay execution. Once Strategy, Risk, and Approval gates succeed, the
candidate is execution-ready and the normal MT5 preflight/order lifecycle runs
immediately.

The delayed two-alert FVG workflow remains implemented behind the setting for
future explicitly approved use. It must not be enabled implicitly.

## Safety Boundaries

- CRT detection and FVG analysis are unchanged.
- Risk approval remains mandatory.
- Manual approval remains governed by `approval.require_manual`.
- MT5 `order_check` remains mandatory before `order_send`.
- Broker rejection, invalid stops, unsupported filling modes, disabled
  algorithmic trading, and ambiguous responses still fail closed.
- The execution ledger records the normal candidate and any broker response.

## Consequences

Subscribers may receive an alert and the approved execution may occur without
waiting for an FVG retest. FVG watch and entry events are emitted only when
the delayed gate is explicitly enabled. Existing delayed requests created
under the previous setting must be reviewed or expired before deployment; they
are not replayed automatically.
