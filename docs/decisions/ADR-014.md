# ADR-014: TradingView Detector Events Start In Shadow Mode

Status: Accepted for shadow mode; live downstream influence not approved  
Date: 2026-08-15  
Decision owner: Project lead  
Authority: `docs/35_WEBHOOK_DOWNSTREAM_CONTRACT_PROPOSAL.md`

## Context

ATLAX now durably authenticates and queues TradingView webhook envelopes, but
the queue must not bypass the Detector, Strategy, Confidence, Risk, Alert, or
Execution boundaries. The webhook payload is external input and can be
incomplete, stale, retired by timeframe policy, or contain an unauthorized
strategy decision.

## Decision

Approve the webhook downstream contract for **shadow processing only**.

The shadow consumer must:

- claim queued events through `WebhookIntakeStore`;
- validate the normalized envelope, source, event type, event timestamp, and
  active timeframe policy;
- require detector provenance and the generic detector output fields defined
  by `docs/07_DETECTOR_SPECIFICATION.md`;
- require non-empty detector evidence and reject detector-provided BUY, SELL,
  or EXECUTE decisions as `UNKNOWN`;
- persist one immutable `OK` or `UNKNOWN` processing result;
- acknowledge the queue item only after that result is persisted;
- retry operational failures and use the existing dead-letter policy.

The shadow consumer must not:

- run a local detector from guessed or incomplete candles;
- create a Trade Candidate;
- calculate or replace ATLAX confidence;
- send Telegram or other alerts;
- approve risk or call MT5.

## Consequences

Valid external detector events can be replayed and audited without changing
live behavior. Incomplete events are visible as `UNKNOWN` instead of being
silently discarded. A later promotion to Strategy requires fixture comparison,
operational monitoring, and a separate approval; this ADR does not authorize
that promotion.
