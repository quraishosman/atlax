# ADR-010: ATR Quality Overlay for Premium Signal Routing

Status: Approved  
Date: 2026-08-13  
Owners: ATLAX Engineering and Project Lead

Approval: Project lead approved live premium routing on 2026-08-13.

## Context

ATLAX already has an approved CRT detector and a standard subscriber signal
route. The project wants to offer premium subscribers a higher-quality signal
stream using ATR-normalized parent range and sweep depth measurements.

Adding those measurements directly to the CRT detector would change the
meaning of a valid CRT and could violate the approved CRT rulebook. Applying
them inside the Risk or Execution Engine would also change automatic trading
behavior and subscriber entitlements would become mixed with execution policy.

## Decision

Introduce ATR quality as a downstream, stateless overlay:

1. The existing CRT detector remains the sole authority for CRT detection.
2. The overlay classifies detected events as `A+`, `A`, `B`, `C`, or `UNKNOWN`.
3. Standard subscribers retain the current delivery behavior.
4. Premium subscribers receive only the configured minimum grade, proposed as
   `A`.
5. The complete signal and ATR result are stored regardless of delivery.
6. ATR quality does not change strategy geometry, risk, stop loss, take profit,
   lot size, or MT5 execution.
7. Advanced maximum-range and volatility-regime rules remain research-only
   until separately approved.

## Mathematical Basis

True Range:

```text
TR_i = max(
    High_i - Low_i,
    abs(High_i - Close_(i-1)),
    abs(Low_i - Close_(i-1))
)
```

Simple ATR used by the current market-data implementation:

```text
ATR_n(t) = sum(last n closed TR values) / n
```

Parent range ratio:

```text
P = (ParentHigh - ParentLow) / ATR_n(t)
```

Sweep depth ratio:

```text
Bullish S = max(0, ParentLow - SweepLow) / ATR_n(t)
Bearish S = max(0, SweepHigh - ParentHigh) / ATR_n(t)
```

Proposed grade bands:

```text
P_HIGH = P >= 0.80       S_HIGH = S >= 0.25
P_A    = 0.60 <= P < 0.80  S_A    = 0.20 <= S < 0.25
P_B    = 0.45 <= P < 0.60  S_B    = 0.15 <= S < 0.20
P_WEAK = P < 0.45        S_WEAK = S < 0.15
```

Proposed grade matrix:

```text
             S_HIGH   S_A   S_B   S_WEAK
P_HIGH          A+      A     A      C
P_A              A      A     B      C
P_B              A      B     B      C
P_WEAK           C      C     C      C
```

Missing or invalid ATR data produces `UNKNOWN` and never passes the premium
filter.

Grades are ordinal for routing:

```text
A+ > A > B > C
```

`UNKNOWN` is non-comparable and fails the premium route.

## Consequences

Positive:

- Premium routing becomes deterministic and explainable.
- Existing standard subscribers are not disrupted.
- CRT detector behavior remains under the approved CRT rulebook.
- Signal Passport and analytics can measure ATR quality over time.
- Automatic execution remains isolated from subscriber entitlements.

Costs and risks:

- The system must maintain an additional quality result and configuration
  snapshot.
- Premium plan entitlements must be stored and expiry-aware.
- Thresholds require project-lead approval and historical validation.
- The current ATR method is a simple True Range mean. Wilder's smoothed ATR is
  the preferred high-priority future method, but changing to it requires a
  separate approved decision and comparison report.

## Rejected Alternatives

### Add ATR sweep thresholds directly to CRTDetector

Rejected because it would change CRT validity and could reject setups that the
approved rulebook currently detects.

### Let premium subscriptions change automatic trading

Rejected because subscriber entitlements must not override Strategy, Risk, or
Execution Engine authority.

### Hardcode the A-grade thresholds

Rejected because ATLAX requires thresholds to flow through the Settings Engine,
be versioned, and be auditable.

## Approval Gates

This ADR was approved after completion of the focused validation suite and
shadow-mode review. The following controls remain mandatory in production:

- ATR calculation method and period behavior.
- A/A+ threshold values.
- Grade matrix boundaries and mixed-quality behavior.
- Premium minimum grade.
- Missing-data behavior.
- Subscription plan entitlement and pricing.
- Shadow-mode validation results.
