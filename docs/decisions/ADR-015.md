# ADR-015: Local MT5 Feed Is The Current Detector Source

Status: Accepted  
Date: 2026-08-15  
Decision owner: Project lead

## Context

TradingView alerts require a paid deployment and are not part of the current
ATLAX operating environment. The local scanner already receives closed market
data from MT5 and runs the documented detector, strategy, confidence, alert,
and execution boundaries directly.

## Decision

The local MT5 market-data feed is the authoritative detector input for the
current deployment. TradingView webhook intake, shadow validation, and replay
fixtures remain optional, dormant integration code. They must not create
candidates, change confidence, send alerts, approve risk, or execute trades.

The active production flow is:

```text
MT5 closed candles -> Detector -> Strategy -> Confidence -> Alert
                                                   -> approved Execution
```

Any future TradingView activation requires a new operational release decision,
real-event observation, and an explicit typed handoff approval.

## Consequences

- ATLAX has no paid TradingView dependency for current signal delivery.
- Local scanner behavior remains the single live detector path.
- Webhook work can continue through fixtures and code-quality checks without
  touching live alerts or execution.
- PostgreSQL cutover applies to the local scanner, API, Telegram, dashboard,
  payments, journal, audit, runtime state, and MCP services together.
